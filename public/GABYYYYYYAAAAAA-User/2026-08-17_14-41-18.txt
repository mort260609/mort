  Yes — these are the areas I'd want to talk through.
  
  **1. Security — the main one**
  
  Right now there's nothing to review. It's a static prototype, so there is no auth layer, no server-side validation, no session handling and no access control. All of it gets built from zero rather than audited. And the moment the system holds CVs, employee records, certificate requests and leave data, you're handling personal data under Saudi PDPL. The pieces carrying the most risk:
  
  - Role-based access control with an editable permission matrix (you confirmed editable, which is meaningfully harder than fixed roles)
  - Preventing one employee from reading another's record by changing an ID or a URL
  - Secure file uploads — CVs and employee documents need MIME and magic-byte validation, size limits, storage outside the web root, and protection against executables disguised as PDFs
  - Internal HR notes that must never leak into the applicant-facing API
  - Secure password reset, sessions, cookies and rate limiting
  
  **2. The frontend is a design prototype, not a working frontend**
  
  The current build is one page with anchor links (#about, #projects, #careers). Your brief needs dedicated project pages, dedicated job pages, breadcrumbs, a sitemap and valid JobPosting schema — none of which can exist on a single URL. Converting anchors into real routes rewrites the navigation, the scroll animations, the language switcher and the project map filters. That's a restructure rather than a fix, and it's why the code structure changes the moment a backend goes in.
  
  **3. Things that read as built but aren't**
  
  - Careers: "Apply now" is a mailto link. No accounts, no CV upload, no tracking UI exists.
  - Employee Portal: the link is href="#", in both the desktop and mobile nav.
  - Contact form: the live site itself says it's a prototype and nothing is sent.
  - Projects: the map is labelled "Sample project set (swap in RCC's real project list)" — 10 hardcoded pins.
  - News and Team: section shells with no records.
  
  **4. Existing bugs, and why they cascade**
  
  - Three stat counters render 0 (team, disciplines, sectors)
  - A stuck 00 counter near the top of the page
  - Est. 2021 in the hero contradicts Founded 1994 in the About section
  - Empty alt attributes on the logo and gallery images
  - Hero video is self-hosted with no poster or CDN; gallery images are injected by JS, so they aren't in the markup
  
  These share dependencies. Getting the gallery images into the markup affects load performance and the lightbox; making the counters fire correctly touches the same scroll observer the section reveals rely on. Each pass needs regression testing, not a one-line patch.
  
  **5. Backend build list**
  
  Foundation: unified account system (applicant / employee / manager / HR / content / website / super admin), authentication, editable permissions matrix, audit logging.
  
  CMS: homepage, about, services, projects, news, team, contact details, media library, editable SEO fields.
  
  Projects: around 20 fields per record, categories, gallery, video, timelapse and drone footage, filtering by sector, region and city.
  
  Careers: job CRUD with publish / unpublish / close / reopen, deadlines, one page per job, applicant registration, reusable profiles, CV and document upload, seven-state application tracking, HR review with internal notes, search and filter, document download.

  Cross-cutting: dynamic Schema.org generated from the database, SEO, hreflang for Arabic and English, performance and image pipeline, backups for both database and uploads, deployment, documentation and handover into RCC's own accounts.
