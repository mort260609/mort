  I found and fixed the root cause. Here is what was going wrong.
  
  ## Root cause
  
  After OTP verification succeeded, the app did this:
  
  1. Cleared `sessionStorage` (registration data)
  2. Showed “Registration submitted! Redirecting…”
  3. Waited 800ms, then navigated to `/register/pending`
  
  **But** a `useEffect` on the OTP page was re-running on every render because the `navigate` function was recreated each time. After storage was cleared, that effect saw “no registration data” and tried to send you back to `/register` — which blocked the redirect to the pending page.
  
  Your backend logs confirm registration **did succeed** (HTTP 201). The failure was only in frontend navigation. Clicking Verify again then showed “OTP not found or expired” because the OTP was already used.
  
  ## Fixes applied
  
  1. **`react-router-dom-shim.tsx`** — Stable `navigate` function (no longer recreated every render)
  2. **`VerifyOtp.tsx`** — Navigate immediately after success (no 800ms delay)
  3. **`VerifyOtp.tsx`** — Do not clear storage until navigation starts; use a `completed` flag so the effect does not redirect back to `/register`
  4. **Backend** — If OTP is already used but the account is pending approval, return `alreadyRegistered: true` and redirect to the pending page
