  # Polymarket Copy-Trading Bot — Full Code Audit & Improvement Task
  
  I have an existing Polymarket copy-trading bot.
  
  ### Current Problem
  
  The current bot mimics the trading activity of top Polymarket traders who were highly active approximately 6 months ago.
  
  This strategy used to perform reasonably well, but recently its profitability has degraded.
  
  I now want to improve the bot so that it can identify and mimic **currently active and consistently performing Polymarket traders**, instead of relying on a static list of traders from the past.
  
  Your job is to first deeply analyze the existing codebase and then propose and implement improvements without unnecessarily rewriting the entire system.
  
  ---
  
  ## 1. First: Understand the Existing System
  
  Before making any changes, inspect the complete repository.
  
  Analyze:
  
  * Backend architecture
  * Polymarket API integrations
  * Wallet/trader tracking
  * Trader discovery logic
  * Trader ranking/scoring
  * Copy-trading logic
  * Trade execution flow
  * Position management
  * Order management
  * Market selection
  * Entry/exit logic
  * Risk management
  * Capital allocation
  * P&L calculation
  * Database schema
  * Cron/background jobs
  * WebSocket/event listeners
  * Queue/workers
  * Caching
  * Error handling
  * Retry logic
  * Rate-limit handling
  * Logging
  * Configuration/environment variables
  * Admin/dashboard functionality
  
  Do not make assumptions about how the system works.
  
  Trace the actual code flow and identify the important files/functions/classes first.
  
  ---
  
  # 2. Create a Current Strategy Audit
  
  Explain exactly how the current bot decides:
  
  1. Which traders to follow
  2. How traders are ranked
  3. Which trades are copied
  4. When trades are copied
  5. How much capital is allocated
  6. Which markets are allowed
  7. Which trades are ignored
  8. How exits are handled
  9. How positions are synchronized

  → Trader Selection
  → Trade Detection
  → Trade Validation
  → Risk Check
  → Position Sizing
  → Order Execution
  → Position Monitoring
  → Exit/Close
  → Performance Tracking
  
  For every stage, reference the actual source files/functions.
  
  ---
  
  # 3. Identify the Main Reason Why Performance Has Declined
  
  Investigate the code and data flow to determine what could cause the old trader list/strategy to become less profitable.
  
  Specifically investigate:
  
  ### Trader Staleness
  
  Check whether the bot is still following traders based on historical performance rather than recent performance.
  
  Determine whether the system considers:
  
  * Recent 7-day performance
  * Recent 30-day performance
  * Recent 90-day performance
  * Trade frequency
  * Recent ROI
  * Recent realized P&L
  * Recent unrealized P&L
  * Win rate
  * Average trade size
  * Number of active positions
  * Current activity
  * Drawdown
  * Consistency
  
  ---
  
  # 4. Design a Dynamic Trader Discovery System
  
  The most important improvement should be moving from:
  
  Static/Historical Top Traders
  
  to:
  
  Dynamic Current Top Traders
  
  Design a system that periodically discovers and evaluates currently active Polymarket traders.
  
  The system should ideally evaluate traders using multiple dimensions instead of simply selecting the traders with the highest historical profit.
  
  Possible factors:
  
  * Recent ROI
  * Recent realized P&L
  * Win rate
  * Risk-adjusted performance
  * Drawdown
  * Consistency
  * Number of trades
  * Trade frequency
  * Average position size
  * Average holding time
  * Current activity
  * Market diversity
  * Recent performance trend
  * Liquidity/volume
  * Position concentration
  
  Do not blindly implement these metrics.
  
  First inspect the existing architecture and determine which metrics can be reliably calculated from available Polymarket data.
  
  ---
  
  # 5. Implement a Trader Scoring Model
  
  Design a configurable trader score.
  
  For example:
  
  Trader Score =
  Recent Performance
  
  * Consistency
  * Activity
  * Risk-adjusted Return
  * Win Rate
  
  - Drawdown
  - Over-concentration
  - Inactivity
  
  The exact formula should be based on your analysis.
  
  Make weights configurable rather than hardcoded.
  
  Example configuration:
  
  RECENT_PERFORMANCE_WEIGHT
  CONSISTENCY_WEIGHT
  WIN_RATE_WEIGHT
  ACTIVITY_WEIGHT
  DRAWDOWN_PENALTY
  RISK_WEIGHT
  
  The scoring system should support time windows such as:
  
  7D
  30D
  90D
  
  Avoid selecting traders purely based on lifetime P&L.
  
  ---
  
  # 6. Avoid Survivorship and Selection Bias
  
  Analyze whether the current implementation has problems such as:
  
  * Only tracking already-famous wallets
  * Selecting traders based only on lifetime profit
  * Ignoring recent underperformance
  * Selecting traders with very few trades
  * Selecting one lucky trader after a short winning streak
  * Ignoring drawdown
  * Ignoring risk
  * Ignoring sample size
  
  Add safeguards where appropriate.
  
  For example:
  
  A trader with +$100,000 P&L from 3 trades should not automatically rank higher than a trader with +$80,000 P&L from 500 consistently profitable trades.

  # 7. Add Trader Lifecycle Management
  
  Design a system where traders can automatically move between:
  
  DISCOVERED
  → EVALUATING
  → ACTIVE
  → WATCHLIST
  → SUSPENDED
  → REMOVED

  For example:
  
  * Newly discovered trader → evaluation period
  * Consistently performing trader → active
  * Performance deterioration → watchlist
  * Excessive drawdown → suspended
  * Long-term inactivity → removed
  
  Do not use arbitrary thresholds without explaining why.
  
  Make thresholds configurable.
