  # Codebase Review: Orderbook Delta Trading Bot
  
  This document provides a comprehensive analysis and review of the **Orderbook Delta Trading Bot** project. It details the system architecture, trading strategy, key findings (including compilation issues, deprecated dependencies, and API mismatches), and structural recommendations for development.
  
  ---
  
  ## 1. Executive Summary
  
  The project is a multi-component algorithmic trading system designed to trade volume delta imbalances (mean reversion strategy) on cryptocurrency markets.
  - **Core Bot**: Built in **Rust** 🦀 for fast, low-latency execution.
  - **Dashboard Backend**: Built in **Node.js (Express & WebSockets)** to stream real-time prices, execute backtests, manage alert conditions, and run strategy optimizations.
  - **Dashboard Frontend**: Built in **React (Vite, Tailwind CSS, Recharts)** for visual analysis.
  - **Deprecated Analyzer**: A Python-based plotting application (`orderbook-delta-visualizer`) that is hardcoded to a defunct exchange.
  
  ---
  
  ## 2. System Architecture & Components
  
  The codebase is divided into three distinct modules:
  
  ```mermaid
  graph TD
      subgraph Rust Trading Bot
          Main[main.rs] --> Helpers[helpers.rs]
          Main --> OrderHandler[order_handler.rs]
      end
  
      subgraph Node.js Backend
          Server[server.js] --> CSV[(positions.csv)]
          Server --> JSON[(settings.json)]
      end
  
      subgraph React Frontend
          UI[App.jsx] <-->|HTTP / WebSockets| Server
      end
  
      Binance[Binance API] <-->|REST API| Main
      Binance <-->|REST API| Server
      Helpers -.->|Write trades| CSV
      JSON -.->|Configuration| Main
      JSON -.->|Configuration| Server
  ```
  
  ### A. Rust Core Bot (`src/`)
  - **[main.rs](file:///c:/Users/DELL/Desktop/new-client/Trading-bot/src/main.rs)**: Orchestrates the core trading loop. It polls the Binance depth API at set intervals, calculates the volume delta, tracks the rolling Bollinger Bands (using the `ta` crate), checks entry triggers, handles trades, and updates local state.
  - **[helpers.rs](file:///c:/Users/DELL/Desktop/new-client/Trading-bot/src/helpers.rs)**: Manages configuration parsing (`settings.json`), CSV trade logging (`positions.csv`), helper utility enums (`Side`), and exponential backoff retry logic for API calls.
  - **[order_handler.rs](file:///c:/Users/DELL/Desktop/new-client/Trading-bot/src/order_handler.rs)**: Interfaces with the Binance API. It generates HMAC-SHA256 signatures, manages market orders, fetches balances, and implements Take Profit/Stop Loss safety triggers via One-Cancels-the-Other (OCO) orders.
  - **[tests.rs](file:///c:/Users/DELL/Desktop/new-client/Trading-bot/src/tests.rs)**: Contains unit tests for helpers.
  
  ### B. Web Dashboard Backend (`web-backend/`)
  - Written in Node.js using Express and WebSockets.
  - Reads local files (`positions.csv`, `settings.json`) generated by the Rust bot to display history and configure parameters.
  - Polls the Binance API every 2 seconds to aggregate market price, orderbook depth, and calculate technical indicators (RSI, SMA, EMA, MACD) in JS.
  - Provides additional API endpoints for:
    - **Backtesting**: Runs a simulated historical Bollinger Band strategy on 1-hour candles.
    - **Strategy Optimization**: Runs a grid search parameter optimizer.
    - **Custom Alerts**: Monitors conditions (e.g., price crossing threshold, RSI boundaries) and broadcasts events via WebSockets.
  - Includes a fallback mock data generator if the Binance API is geo-blocked (HTTP status 451).
  
  ### C. Web Dashboard Frontend (`web-frontend/`)
  - Built using React 18, Vite, Tailwind CSS, and Recharts.
  - Listens to WebSocket events on `ws://localhost:8080` for real-time orderbook, price, and indicator charts.
  - Provides forms to trigger backtests, check parameter optimizations, configure alerts, and view position history.
  
  ---
  
  ## 3. Trading Strategy Analysis
  
  The bot implements a **mean reversion** strategy utilizing orderbook volume imbalance.
  
  ### Key Metrics
  1. **Orderbook Depth**: Sums bid and ask volumes up to a specified depth (default: 5 levels).
  2. **Bid-Ask Delta**: Calculated as:
     $$\text{bid\_ask\_delta} = \sum_{i=1}^{\text{depth}} \text{BidVolume}_i - \sum_{i=1}^{\text{depth}} \text{AskVolume}_i$$
  3. **Bollinger Bands (BB)**: Tracks a 20-period moving average of the `bid_ask_delta` with a 2-standard-deviation boundary.
  
  ### Entry & Exit Logic
  - **Short Entry**: Triggered when `bid_ask_delta` crosses above the upper Bollinger Band. This indicates an unusual buyer imbalance, implying overextended buying pressure that should mean-revert.
  - **Long Entry**: Triggered when `bid_ask_delta` crosses below the lower Bollinger Band. This indicates an unusual selling pressure, implying an oversold condition.
  - **Exit Conditions**: Protected by static Take Profit (TP) and Stop Loss (SL) levels set via Binance OCO orders (e.g., default TP: 0.2%, SL: 0.1%).
  
  ---
  
  ## 4. Key Issues & Bugs Identified
  
  ### 🔴 Critical: Rust Unit Test Compilation Failure
  The unit tests in `src/tests.rs` fail to compile. During a previous refactoring, the field `time_delta` in `SettingsFile` was renamed to `sampling_time` in `helpers.rs` and `main.rs`. However, the test file still attempts to initialize and assert on `time_delta`:
  - **Line 47**: `time_delta: 1,` (Struct initialization error)
  - **Line 62**: `assert_eq!(settings.time_delta, 1u64);` (No such field error)
  
  ### 🔴 Critical: Spot API Mismatch for Futures Strategy
  The Rust bot's logs and strategy description state that it targets the **futures orderbook delta** to counter-trade over-leveraged liquidations. However:
  - The API endpoints used throughout `src/main.rs` and `src/order_handler.rs` point to Binance Spot:
    - `https://api.binance.com/api/v3/depth`
    - `https://api.binance.com/api/v3/order`
  - Spot accounts do not support leverage, and placing a "SELL" order without owning the asset first will result in an API error (insufficient balance) rather than opening a short position. True shorting requires the Binance Futures API (`https://fapi.binance.com`).
  
  ### 🟡 Warning: Deprecated Python Visualizer
  The `orderbook-delta-visualizer` sub-project (written in Python with Dash/Plotly) is hardcoded to use the **FTX exchange** websocket client (`FtxClient`, `FtxWebsocketClient`). FTX went bankrupt and shut down in November 2022. As a result, this visualizer will fail to launch or query any endpoints.
  
  ### 🟡 Warning: REST API Polling Rate Limits
  The Rust bot uses synchronous polling (`std::thread::sleep(std::time::Duration::from_secs(1))`) to fetch the orderbook via GET requests to `/api/v3/depth`. Rapid polling can easily lead to Binance API rate-limit bans (HTTP status 429), especially when running concurrent requests from the Node.js backend.
  
  ---
  
  ## 5. Architectural Recommendations
  
  To improve stability, safety, and functionality, the following updates are recommended:
  
  1. **Fix Test Suite Compilation**:
     Rename `time_delta` to `sampling_time` in `src/tests.rs` to allow code verification via `cargo test`.
  
  2. **Migrate to Binance Futures API (`fapi`)**:
     Change base URLs in the Rust code from `https://api.binance.com/api/v3` to `https://fapi.binance.com/fapi/v1` to enable true leveraged long and short contract trading.
  
  3. **Transition to WebSocket Streams**:
     Replace REST polling in the Rust bot with a WebSocket connection to Binance's live orderbook depth stream:
     `wss://stream.binance.com:9443/ws/btcusdt@depth5`
     This will eliminate latency and completely remove HTTP rate-limiting risks.
  
  4. **Retire or Rewrite Python Visualizer**:
     Since the React web dashboard already handles live visualization, backtesting, and parameters optimization, the Python FTX visualizer is redundant. It should either be updated to Binance Spot/Futures or removed from the repository.
