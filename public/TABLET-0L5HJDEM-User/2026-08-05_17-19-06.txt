  Root cause
  
  v7.23 added YOLOv8 (ultralytics + PyTorch) for people-detection in photos, with yolov8_enabled = True by default. But:
  
  build_mac.sh never installs ultralytics, and
  skyedit_mac.spec never bundles torch/ultralytics or yolov8n.pt.
  
  PyTorch is ~2GB and notoriously breaks PyInstaller macOS .app bundles. The result is the classic symptom: the app shows the launch/verify progress bar, hits a fatal error during startup, and quits without opening.
  
  Fix applied (safe, keeps photos working)
  
  YOLO is only a photo-quality booster; photo selection already has a full fallback (YuNet + subject/sharpness scoring), so it's not core to the reel.
  
  Engine auto-disables YOLO in frozen builds. New _yolov8_default_enabled():
  OFF when frozen (packaged .app/.exe)
  OFF from source unless ultralytics is importable
  Override anytime with SKYEDIT_ENABLE_YOLO=1 / =0
  No online model download in a frozen app. _get_yolo_model() now loads a LOCAL yolov8n.pt only (a download attempt could hang a windowless app).
  Spec excludes the torch/ultralytics stack (skyedit_mac.spec) so PyInstaller cleanly skips them instead of failing to collect them.
  build_mac.sh notes that YOLO/torch are intentionally excluded.
  Result
  The .app no longer tries to load torch at startup → builds and launches reliably.
  Photos still avoid empty-sky frames via the YuNet/subject-scoring fallback.
  YuNet face detection is UNAFFECTED (it uses OpenCV's DNN, cv2.FaceDetectorYN, not the excluded onnxruntime package).
  If you WANT YOLO later
  
  Run from source with pip install ultralytics (keep yolov8n.pt next to the app or in models/), or set SKYEDIT_ENABLE_YOLO=1. For a bundled app it's not recommended — the size/fragility isn't worth a photo-scoring boost.
