  # 44Craft — Follow-up: Real Upload Flow for Project & Community Images
  
  ## Context
  Project cover/gallery images and community update images currently
  require manually uploading through the Supabase dashboard directly
  and pasting the resulting URL into the admin form — the only asset
  type with a real in-app upload flow is team profile photos. This
  closes that gap, reusing the same pattern that already works.
  
  ## What to build
  1. **New Storage bucket(s)** — following the `team-photos` pattern
     (public, size/type limits enforced client and server side). Either
     one shared bucket for project/community images or separate ones
     per content type, whichever fits the existing storage setup
     script's pattern more naturally — your call, just stay consistent
     with how `team-photos` was set up.
  
  2. **Upload UI in the admin forms** — project cover image, project
     gallery (multiple images), and community update image all get a
     real upload button/dropzone in their respective admin forms
     (`/admin/projects`, `/admin/community`), same interaction pattern
     as the profile photo uploader already used in
     `/dashboard/profile`. On successful upload, the resulting Supabase
     Storage URL populates the field automatically — no manual URL
     pasting required for the normal path.
  
  3. **Keep the existing validation** — the Supabase-hostname check
     from the last fix stays in place as a safety net; this just means
     the normal flow now naturally produces a URL that already passes
     it, instead of relying on someone reading the hint text and doing
     the right thing manually.
  
  ## Explicitly out of scope
  No changes to the image allowlist decision (still Supabase-only, per
  the last fix) — this is purely adding the missing upload UI, not
  revisiting that decision.
  
  ## Verify
  Upload a real image through each of the three new upload points
  (project cover, project gallery, community update), confirm the
  resulting URL is a real Supabase Storage URL, and confirm the image
  actually renders on the corresponding public page. Confirm typecheck/
  lint/build pass clean.
