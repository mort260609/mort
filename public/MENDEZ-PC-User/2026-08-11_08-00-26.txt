  # Frontend: Fail Loudly on Missing Environment Variables
  
  Per Dmitry's review: `constants.ts` currently falls back to fake
  placeholder addresses (`0x1111...`, `0x2222...`, etc.) if the
  `VITE_*` env vars are missing. This means forgetting to copy
  `.env.example` → `.env` results in the app silently running against
  garbage addresses instead of failing clearly — confusing to debug,
  since it looks like a real bug rather than a missing setup step.
  
  ## Fix
  
  Replace the placeholder-fallback pattern with an explicit check that
  throws a clear error at startup if any required `VITE_*` variable is
  missing or empty. Something like:
  
  ```typescript
  function requireEnv(key: string): string {
    const value = import.meta.env[key];
    if (!value) {
      throw new Error(
        `Missing required environment variable: ${key}. Did you copy .env.example to .env?`
      );
    }
    return value;
  }
  ```
  
  Apply this to every address currently using the placeholder-fallback
  pattern (`NexaiIndexToken`, `NexaiCore`, `WETH`, `USDC`, `NexaiZapper`,
  `USDT`, and any others in the file).
  
  ## Requirements
  
  - Error message should be clear enough that someone unfamiliar with
    the project understands exactly what to do (copy `.env.example` to
    `.env`), not just "missing env var"
  - This should fail at app startup/build time, not silently later when
    a specific function happens to get called
  - Verify the app still builds and runs correctly with a properly
    configured `.env` (i.e. confirm this doesn't break the working case,
    only fixes the broken/missing case)
  
  ## Notes
  
  - Small, contained change — no other functionality should be affected
  - Testnet only, no mainnet
  - Standard process: confirm build succeeds, paste the actual updated
    `constants.ts` here for review before considering this done

  Threshold logic, spelled out: the outer Safe is 2-of-2 (MENDEZ, innerSafe), not 2-of-3 — its only two owners are Mendez and the inner Safe itself. That means Mendez alone can never act; every action needs Mendez's signature and the inner Safe's approval (which itself only needs one of Dmitry's two backups to sign). If a single Dmitry backup key is lost, the inner Safe still functions (1-of-2), so this doesn't create a lockout risk on that side — but if Mendez's key is ever lost, the whole outer Safe is permanently stuck, since 2-of-2 has no redundancy on that leg.
