  # 44Craft — Phase 7: Projects, Services & Community Pages
  
  ## Context
  Read SPEC.md before starting, particularly Section 6 (page specs)
  and Section 5 (data models). Phases 1, 2, 3, 5, and 6 are complete —
  auth/invites, design system, homepage, real team system, and the
  real admin dashboard (with CRUD for projects/services/community
  updates) are all live. This phase builds the public-facing pages
  that render the content admin can already create.
  
  ## Assumption — flag if wrong
  No confirmation yet on whether there are real projects to populate
  `/projects` with. Building this with a "coming soon" empty state as
  the default (same pattern already established on `/team` — clean,
  intentional-looking, not a broken/blank page), swappable the moment
  real projects get entered through the Phase 6 admin CRUD. If real
  projects already exist in the DB, just render them instead of the
  empty state — check before assuming zero.
  
  ## 1. `/projects` (index) + `/projects/[slug]` (detail)
  **Index:** grid of project cards — cover image, title, service tags,
  avatar stack of team members involved (pulled from `teamMembers` on
  the project data model, linking to their `/team/[slug]` pages).
  Empty state per the assumption above if nothing's published yet.
  
  **Detail:** banner/cover image, title, description, tags that link
  back to the matching `/services/[slug]` page, a "Built by" avatar row
  linking to each team member's `/team/[slug]`, image gallery if the
  project has one, "Visit live site" external link if applicable,
  next/prev navigation between projects.
  
  ## 2. `/services/[slug]` (detail pages)
  The `/services` index already exists from Phase 3 and links out to
  these — build the pages it's pointing at:
  - Full description, deliverables list
  - "Who you'd work with" — team members whose skills match this
    service (reuse the reverse-link logic already built for
    `/team/[slug]`'s "services covered" section, just inverted)
  - Related past projects tagged under this service (empty state if
    none yet, same principle as above)
  
  ## 3. `/community`
  Per SPEC.md Section 6:
  - Vision statement front and center — reuse the real brand-voice copy
    already used in the homepage About section, don't write new copy
    that might drift from it
  - Partners showcase — Chronara AI Africa and Starmark, real depth per
    partner (not a logo strip), tone matching the actual "official
    partnership, aligned for the long term" language from the brand's
    own X posts (SPEC.md Section 1)
  - Real, honestly-scaled stats — no inflated numbers, consistent with
    the project's standing "early but real" principle
  - Join CTA (Discord/Telegram) — if the actual link isn't available
    yet, use a clearly-marked placeholder and flag it rather than
    linking nowhere or guessing a URL
  - Updates/highlights feed — pulls from the community_updates data
    admin can already create via the Phase 6 CRUD; empty state if
    nothing's been posted yet
  
  ## Design consistency
  All of this follows the same system as everything else at this
  point — dark canvas, gold accents on objects/icons only, the
  established card language (border glow, hover lift), entrance motion
  on scroll (`riseIn`/`Reveal` — use the on-mount-safe version, not the
  scroll-trigger version that caused the invisible-button bug in
  admin, if any of this renders content that could be in-viewport on
  load).
  
  ## Explicitly out of scope
  - Email notifications (Phase 8)
  - Any admin-side changes — the CRUD for these already exists from
    Phase 6, this phase is display-only
  - The homepage skill-filter/spark-burst teaser, if it's still not
    built (separate, already-flagged item)
  
  ## Deliverable
  Working `/projects`, `/projects/[slug]`, `/services/[slug]`, and
  `/community` pages, all rendering real data from the admin CRUD (or
  clean empty states where nothing exists yet), fully cross-linked with
  `/team/[slug]` and each other. Confirm typecheck/lint/build pass
  clean, and check on a real mobile device — not just resize-the-browser
  — given mobile issues have been missed by build-only checks before on
  this project.
