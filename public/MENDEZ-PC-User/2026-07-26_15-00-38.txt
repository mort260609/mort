  # Phase 4.5 — Unified Emoji / GIF / Sticker Picker + Media Status Check + Custom Camera
  
  ## Context
  This follows Phase 4 (media sharing: images, video, docs, voice notes). Reference the current ARCHITECTURE.md and do the standard "audit real codebase first" check before building anything.
  
  ## Part A — Status check first, before new work
  
  Images are sending/displaying correctly, but video, documents, and PDFs don't seem to send yet — these were in Phase 4's original scope. Before starting the new work below, please confirm: is this simply still in progress, or is there an actual bug blocking these specific media types? Give an honest status on each media type separately, and fix/finish whatever's incomplete before or alongside the rest of this round.
  
  ## Part B — New scope: custom in-app camera (not just native camera launch)
  
  What was originally scoped for Phase 4 was calling the phone's native camera app via a simple picker launch. What's actually wanted is a full custom in-app camera experience, similar to WhatsApp's — rendered live inside Gist itself, not handed off to the OS camera app. Specifically:
  
  - Live camera preview rendered inside the app (using expo-camera, not expo-image-picker's launchCameraAsync)
  - Custom capture button, styled to match our design system (indigo/coral/adire tokens)
  - Flash toggle, front/back camera flip
  - Photo capture at minimum; if reasonable to include, a photo/video mode toggle so the same in-app camera can also record short videos directly (tying into the video-sending pipeline from Part A)
  - This becomes the new destination when tapping the camera icon in the input bar, replacing the simple native-picker approach
  
  This is a meaningfully different technical piece than file upload/encryption (live camera rendering, permissions, platform differences) — please assess whether it needs its own dedicated testing/verification pass separate from the rest of this round.
  
  ## Part C — Unified Emoji / GIF / Sticker picker
  
  ### Reference
  WhatsApp Web's compose panel: tapping the emoji icon in the input bar opens a panel with three tabs — Emoji, GIF, Sticker — searchable, tap to insert/send. This is the exact pattern to follow.
  
  ### 1. Emoji tab
  A proper emoji picker UI (categories, search) that inserts the selected emoji into the current text input at the cursor position — not for reactions (that already exists via long-press), this is for composing messages with emoji.
  
  ### 2. GIF tab
  - Integrate with a GIF provider API — Giphy or Tenor, both have usable free tiers. Please check current pricing/rate limits for each before picking one, since this may have changed since training data.
  - Search-as-you-type, grid of results, tap to send directly as a message (reusing the media pipeline from Phase 4 where sensible)
  - Consider: does a sent GIF need E2E encryption the same way user-uploaded media does? A GIF from a public API isn't private content the same way a photo is — worth deciding whether to just store/reference the GIF URL directly (simpler, arguably fine since the content is already public) versus encrypting it unnecessarily. Please propose your reasoning before implementing.
  
  ### 3. Sticker tab
  - Start with a basic open/free sticker pack to prove out the feature (confirm licensing allows use in an app before including any set)
  - Architecture should support adding more sticker packs later, including potentially custom Adire-themed stickers as a future on-brand addition — don't architect this in a way that makes adding packs later painful
  
  ## Explicitly out of scope for this round
  - Custom sticker creation/upload by users
  - Trending/featured GIF sections beyond basic search
  
  ## Acceptance criteria
  - [ ] Video, documents, and PDFs all send/display correctly end-to-end (Part A)
  - [ ] Custom in-app camera opens, captures a photo (and ideally video), sends correctly, matches app design (Part B)
  - [ ] Tapping the emoji/GIF/sticker icon opens a tabbed panel matching the reference pattern (Part C)
  - [ ] Emoji tab correctly inserts emoji into the compose text input
  - [ ] GIF tab successfully searches and sends a real GIF end-to-end
  - [ ] Sticker tab sends a sticker successfully end-to-end
  - [ ] No regressions to any previously verified functionality
  
  ## Testing requirement
  Same standard as always — verify real behavior, flag anything you cannot personally verify, show actual evidence not just code descriptions. Given the scope here spans three fairly different technical areas (media/status fixes, live camera, third-party API integrations), please propose whether this should be split into sub-rounds before starting, same as past larger phases.
